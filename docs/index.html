Lint your MCP server while you write it

MCP Lint is a VS Code extension that watches your server.tool(...) and server.registerTool(...) calls and reports problems the moment you introduce them — the same way ESLint or a type checker would. No separate CLI, no pointing at a running server.

What it catches

Six diagnostic rules, all with one-click Quick Fixes. Open examples/bad-server.ts to see every rule fire at once.

mcp-lint/missing-description error

Missing or empty tool description

Agents choose which tool to call by reading the description. A tool with no description is effectively invisible to the model.

❌ Flagged
server.tool('delete_file', { path: z.string() }, async ({ path }) => {
  // ✗ no description argument at all
});
✅ Fixed
server.tool('delete_file', 'Delete a file by its path.',
  { path: z.string() }, async ({ path }) => {
  // ✓ description tells the model what this does
});
mcp-lint/duplicate-tool-name error

Duplicate tool name

Registering two tools with the same name means only the first one is reachable at runtime. The second registration silently shadows nothing.

❌ Flagged
server.tool('list_files', 'List files.', async () => { … });

// ✗ 'list_files' was already registered above
server.tool('list_files', 'List files again.', async () => { … });
mcp-lint/generic-param-name warning

Overly generic parameter names

Names like data, value, input, or payload give a model nothing to reason about. Prefer descriptive names like repositoryUrl or maxResults. The list of flagged names is configurable.

❌ Flagged
inputSchema: {
  data: z.any(),   // ✗ too generic
  value: z.string(), // ✗ too generic
}
✅ Fixed
inputSchema: {
  recordId: z.string().describe('The ID of the record to update'),
  newValue: z.string().describe('The new value to set'),
}
mcp-lint/description-bloat warning

Description token-bloat

Long descriptions cost context on every single call. Keep descriptions tight and move detail into per-parameter .describe() calls. Default threshold: 120 tokens (configurable via mcpLint.maxDescriptionTokens).

❌ Flagged (100+ tokens)
server.tool('send_email',
  'Sends an email to a recipient. This tool should be used
   whenever the user wants to communicate with someone via
   electronic mail, which is a system for exchanging digital
   messages between people using digital devices …',
  // ✗ 100+ whitespace-separated tokens
  { … });
mcp-lint/missing-param-description info

Missing per-parameter .describe()

Schema properties without a .describe(...) call give a model nothing to go on for that field. Enabled by default; toggle via mcpLint.requireParamDescriptions.

❌ Flagged
{ query: z.string() }  // ✗ no .describe()
✅ Fixed
{ query: z.string().describe('The text to search for') }
mcp-lint/malformed-schema error

Malformed input schema

The MCP SDK expects a plain object of Zod validators (a ZodRawShape), not a z.object(...) call. Also flags empty {} schemas — either define the parameters or omit the argument.

❌ Flagged
server.tool('search', 'Search.',
  z.object({ query: z.string() }),  // ✗ z.object() wrapper
  async () => { … });

server.tool('list', 'List.', {}, async () => { … });
// ✗ empty {} schema
✅ Fixed
server.tool('search', 'Search.',
  { query: z.string().describe('Search query') },
  async () => { … });

One-click Quick Fixes

Most issues ship with a Code Action — hit Ctrl+. / Cmd+. or click the lightbulb:

  • Insert a TODO description — for missing descriptions on either call shape
  • Unwrap z.object(...) — into a raw Zod shape
  • Scaffold an empty input schema — with a TODO placeholder parameter
  • Add a TODO .describe(...) — to an undocumented parameter

Also included

🔬 Inspector CLI bridge

"MCP Lint: Run MCP Inspector CLI on This File" shells out to npx @modelcontextprotocol/inspector --cli and surfaces the result as a diagnostic plus full raw output in the "MCP Lint: Inspector" output channel.

📊 Workspace-wide scan

"MCP Lint: Scan Workspace for Problems" lints every .ts/.tsx/.js/.jsx file in one pass — useful before a commit or PR. A status bar item shows the live total problem count.

⚡ Updates as you type

Diagnostics appear as squiggly underlines and in the Problems panel, updating on every keystroke (debounced 300 ms) and on save. No separate build step, no CLI to remember.

🎯 Syntax-level, not guesswork

The analyzer only reasons about literal arguments in source text and intentionally skips anything passed via a variable — no false positives from dynamic code.

Quick start — 3 commands

Clone, install, compile. Then press F5. 

$ git clone https://github.com/CuplexUser/mcp-lint.git
$ cd mcp-lint && npm install
$ npm run compile

Open the folder in VS Code and press F5 (Run → Start Debugging) to launch an Extension Development Host with MCP Lint active.

See it in action in 30 seconds: open examples/bad-server.ts to see every rule fire, or examples/good-server.ts to confirm a clean file reports zero problems.

Or package a .vsix for permanent install 
$ npm install -g @vscode/vsce
$ vsce package

Install the resulting .vsix from the Extensions view's "…" menu → Install from VSIX.
